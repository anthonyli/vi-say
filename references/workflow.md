# 共用制作流程

本页只维护场景选择、阶段顺序和工具路由。每个阶段的默认偏好、输入输出和检查放在对应 `stages/*.md`，参数扩展见 [extensions.md](extensions.md)。

## 选择内容场景

| 场景 | 先理解什么 | 需要的素材 |
|---|---|---|
| GitHub／开源项目分享 | 问题、特点、用法和适用人群 | README、文档、真实演示 |
| 官网／产品分享 | 使用场景、功能与操作 | 官网说明、截图、录屏 |
| 文章／其他链接分享 | 原文结论、条件与重点 | 原文、数据和引用 |
| 播客／长访谈精华 | 给目标观众讲清楚哪几条观点、依据和条件 | 节目章节、转写、原画或相关证据。走[播客精华路线](tools/podcast-highlights.md) |
| 已录视频剪辑 | 原声意思、有效片段、重复或口误 | 原视频、转写、剪辑区间 |
| 知识科普／原理解说 | 概念、因果、关系与理解难点 | 可靠资料和明确标识的示意 |
| 实战案例／过程复盘 | 目标、过程、前后变化与结果 | 原始状态、实际操作、完成效果 |

场景可以组合；底层复用同一组声音、海报、动画与交付能力。资料读取与写作由 Agent 使用当前可用工具完成，技能没有统一的链接抓取服务。

## 制作前的项目约定

在本期 work 目录简要记录：受众/语气、交付范围、开场与片尾、已认可参考的文件/版本、必须保留的内容、未解决问题及验证方式。将“参考海报”拆成字形、素材、构图、背景色、镜头与运动等维度；认可其中一项不推定全部照搬。分别记录画面参考和运动参考，避免换材质时丢掉已认可的镜头与动作。连续反馈累积更新这份约定，不让最后一句覆盖早先要求；已有决定无需重问。

完整自媒体项目从一开始登记[交付清单](tools/delivery-check.md)。开工时列出交付范围，按 [HTML 前审设置](#html-前审) 决定何时制作海报、发布文案和发布包。

## 流程节点

| 顺序 | 节点与独立规范 | 输出 |
|---|---|---|
| 1 | [内容理解](stages/content.md) | 本期受众、主要问题、核心收益、提纲与素材依据 |
| 2 | [脚本](stages/script.md) | 完整口播，或原声内容的保留与重组方案 |
| 3 | [分镜](stages/storyboard.md) | 各段的论点、对象、状态变化和预期触发词 |
| 4 | [声音](stages/voice.md) | 剪辑母版或授权配音、最终 WAV 和真实检查记录 |
| 5 | [字幕与语义时间](stages/captions.md) | 可靠词时间、字幕、画面动作锚点 |
| 6 | [画面与图解](stages/visuals.md) | 真实演示、角色、流程、比较或图表 |
| 7 | [动画与样片](stages/animation.md) | 连续动作、转场与实渲样片，修订后扩展全片 |
| 8 | [互动片尾](stages/outro.md) | 与本期声音一致的结尾口播、画面和动作 |
| 9 | [HTML 前审](#html-前审) | 有声预览、自查报告和用户确认的版本记录 |
| 10 | [海报](stages/poster.md)与[发布文案](stages/publishing-copy.md) | 按确认的内容生成所需比例海报、标题、正文、相关链接和话题 |
| 11 | [检查与交付](stages/delivery.md) | 成片、音轨、所需字幕、三比例海报及检查记录 |

片尾稿在生成完整声音时一并加入；先规划完整故事，再按节点分别核对，不把独立文档误解为最后才拼贴声音。无声样片跳过配音并标清范围，不能声称完成声音验收。

最终交付复核海报与成片一致，复用已有合适海报，每个缺失且尚未生成的所需比例默认只生成一次。修改及停止条件见 [海报节点](stages/poster.md#生成次数与停止条件)。

## HTML 前审

新制完整视频在渲染前读取前审设置。优先级依次为本次明确要求（如「这期跳过 HTML，直接出视频」）、本期 `project.json`、本机 `private/production-preferences.json`、技能默认值。两个文件使用同一个顶层字段 `html_review`，可填 `required` 或 `skip`。长期希望直接出视频时，在本机偏好文件写入 `{"html_review": "skip"}`。运行 `python scripts/production.py review-mode PROJECT/project.json` 查询生效值，显式指令可用 `--html-review required|skip` 传入。

- **`required`（默认）**。先制作口播、画面、字幕和片尾，用 `production.py review` 生成浏览器预览和自查包。先查看 `self-check/` 的场景、转场与报告，修完再送审。有声项目用正式口播与对齐后的时间轴。预览确认前只登记配套交付范围。收到用户对当前版本的确认后，记录其原话、预览路径和版本，再用同一批素材与时间轴渲染完整 MP4，并制作本期所需的海报、发布文案和发布包。画面或声音改动后重新生成预览并复查变更。收到明确的平台发布授权后才执行发布。
- **`skip`**。沿所选路线直接制作与渲染，按节点验证音画同步、字幕和最终输出。可在内容提炼后先展示代表海报，发布文案按稳定后的内容起草。

用户确认前审并要求完整发布交付时，用 [`promote-delivery`](tools/delivery-check.md#将已确认的前审转为正式发布交付) 建立正式清单，再制作和验收配套产物。用户明确要求先看海报或单独制作海报、发布文案时，按该任务范围执行。已有合适的配套素材直接复用。

HTML 前审统一使用[公共播放器](tools/production.md#浏览器前审)。深色页面内居中显示原画幅，播放控件在画面下方，逐句「字幕导航」默认展开。标准时间轴、漫画录屏和自编录屏共用这套布局。自编工程传入本期的画面组件、字幕和最终渲染素材。仅执行局部修订、独立样片、音频处理或已有成片交付时，沿用本期明确约定。

## 更换自己的偏好

先改对应阶段的“可替换偏好”，参数修改指向实际配置，新增行为指向实际代码。默认角色与色板分别在 [character.md](styles/character.md)、[colors.md](styles/colors.md)，视频和海报可以有独立配色。

单期选择保存在本期任务记录，只有希望改变所有后续默认行为时才修改公共规范。修改一个模块不默认重做其他已认可内容；声音和时间变化则重绑相关字幕、口型与动作。真实素材、音画同步、最终声音时间、真实检查和私有资料边界持续保留。

小龙系列默认使用 [漫画积木风](styles/comic-bricks.md)，替换旧玻璃／灰绿默认方向。讲解视频走 `production.py init` 的默认 `comic` 预设，版式、动效和转场由公共代码固定；每期按主题选择背景色、高亮与素材，不另写渲染工程。真实产品录屏承担主要讲解，气泡和积木用于引导与归纳。
