# 口播脚本与内容表达

输入是内容提纲、素材依据和前置海报方向；输出是完整口播与章节逻辑，交给 [分镜](storyboard.md) 和 [声音](voice.md)。

## 可替换的写作偏好

| 项目 | 默认处理 | 可调整方向 |
|---|---|---|
| 语气 | 自然、具体、像向观众讲清一件事 | 专业、轻松、故事化、教学式 |
| 叙述结构 | 根据问题选择，不固定套功能列表 | 案例→过程、结论→证据、比较→选择、原理推导 |
| 开头 | 尽早给出相关问题或真实可见结果 | 提问、反差、操作结果、简短故事 |
| 篇幅 | 服从有效内容与任务要求 | 调整深度、例子与节奏，不靠全片倍速凑长度 |
| 互动 | 本期相关问题与系列收尾 | 视频片尾见 [outro.md](outro.md)，发布正文见 [publishing-copy.md](publishing-copy.md) |

这些是本节点的默认写法，可以改成使用者自己的表达习惯；事实、条件与素材依据持续保留。

## 正常写稿

先完整写成自然语义段落，包含本期需要的 [互动片尾](outro.md)，再设计字幕，不按字幕行切成单句 TTS。每段推进一项新信息，讲操作时写出对象、动作和结果，讲原理时明确关系；口播、海报和画面围绕同一本期问题。

已有录屏默认整理原声，不自动替换为 TTS。用户明确要重配音时先改稿，最终原片静音并重新对齐。英文品牌、数字与多音词交给本期术语表，显示稿保留准确原名，不杜撰另一种产品名。

## 传播优化（按需要）

用户要求“爆款”或“吸引眼球”时，把目标落实为观众愿意停留、看完、分享或采取行动的表达；不能保证实际流量。保留当次受众、产品和用途，不把某个案例固化成全部视频的主题。

## 先理解，再重写

- 转写原始口播并检查关键画面，整理：用户痛点、实际做了什么、已经展示的结果、仍属设想的能力。识别不清的专有名词要核对，不能把 ASR 错字当品牌事实。
- 分清操作过程和效果素材。优先用真实结果证明开场承诺，再回到关键操作；聊天中的完成报告与可见效果不是同一种证据。
- 从用户背景推断核心受众和主要传播目的；只有关键歧义会改变选题时才问。区分吸引泛流量、吸引同行关注、带来产品试用，不把三个目标平均堆在一条短视频里。

## 口播与画面要求

- 开头约 3–5 秒直击一个具体矛盾、反差或可见收益，尽早给出结果镜头。避免自我介绍、版本履历和长铺垫；画面必须能兑现钩子。
- 围绕一个核心承诺组织完整故事：困境或愿望 → 实际动作 → 结果证据 → 对观众的价值。根据素材调整顺序，不机械套模板。
- 用口语短句和具体动作说明能力，每段推进新信息。按语义安排画面变化、关键词和前后对比，避免用密集特效补偿信息空洞。
- 强钩子来自真实反差；不用捏造收入、节省时长、成功率、用户数或虚假紧迫感。“全自动”“只需一句话”“零人工”等表述需要完整流程证据，并说明实际仍由人负责的决策、授权与检查。
- 原素材有更强表达机会时可重排和压缩，不改变事实、条件和因果。替换配音后重新建立声音时间轴，避免保留旧录音、双重人声或按旧字幕时间硬套新稿。
- 标题、封面、前几秒围绕同一个收益；封面保留一个主句和一个视觉焦点。最终选一个主标题，可附少量不同角度备选；不要用堆叠感叹号代替信息。
- 收尾只推动一个主要行动，呼应观众刚获得的价值；遵循用户的互动收尾偏好，不在结尾继续加入新主题。

## 交付前检查

检查开场是否立即指向受众、是否尽早展示证据、每项能力是否有素材支持、冗余解释能否删掉、标题承诺是否兑现。说明这是传播优化方案，真实传播效果需发布数据验证；没有数据时不虚构验证结果。用户只要求理解或改稿时交付对应成果，不擅自发布。
