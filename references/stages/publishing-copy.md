# 发布文案风格

生成每期发布标题、正文和话题前读取本文件。默认沿用自然、具体的个人分享口吻；统一语气与组织方式，每期根据内容重新写，不逐句套同一个开头和结尾。当次用户要求优先。

## 可调整的默认设置

| 项目 | 默认写法 |
|---|---|
| 语气 | 像向朋友分享工具或一次实践，口语化、直接、有具体场景 |
| 标题 | 一个具体问题、收益或真实事件，加上必要的项目名；优先一句话说清 |
| 正文长度 | 通常约 200–350 字，按内容增减；短段落，不为凑字数扩写 |
| 开头 | 从使用场景、遇到的问题或确实发生的事情切入 |
| 内容重点 | 真实经历与个人判断，再说明这期分享什么、能用在哪、最值得说明的 1–2 个特点 |
| 互动 | 一个和本期相关、容易回答的问题，再简短邀请点赞或关注 |
| 话题 | 通常 3–5 个，项目名加相关领域，避免无关热门词 |
| 表情 | 默认不用，不连续堆叠感叹号 |
| 链接 | 有需要时在正文后单列核实过的官网或项目地址 |

调整风格主要修改此表和下面的示例，不需要改视频、海报或声音配置。平台有标题或长度限制时优先满足实际限制。

## 写作方式

顺着读者的问题展开：具体场景 → 本期工具或实践 → 实际用途与关键特点 → 必要的使用提示 → 相关互动问题。按内容合并或省略段落，不要求每期固定五段。

- 用“写邮件、记灵感”这样的具体事情说明用途，少写空泛的“提高效率、赋能创作”。正文补充观看理由，不直接粘贴整段口播。
- 有真实经历时可以写“我用……”“这次做了……”，但必须来自用户提供或实际记录。只有官方资料与演示时，写“这次分享……”或“这期介绍……”，不虚构长期使用、亲测效果、性能提升或个人感受。
- 标题可以有吸引力，但“效果惊艳”“终于解决”等评价必须有真实依据，不照搬往期项目的结论到新项目。
- 只介绍视频确实涉及且已核实的能力。安装条件、适用范围等确实影响理解时，融入一句自然提示，不把正文写成参数表或检查报告。
- 发布文案的结尾按本期主题写问题，例如“如果把打字换成说话，你最想用在哪个场景？”；视频内的固定片尾仍由 `assets/production/outro.json` 管理，不机械复制三句互动口号到发布正文。
- “制作说明、来源记录、待听审项”等交付信息另放记录文件；若涉及实际发布需披露的信息，按要求保留，不能借精简文案隐去。
- 用户分享自己制作的产品宣传片时，先分清传播的是“制作作品”还是“产品销售”。作品分享可用真实的制作对象、成片时长和可见效果构成钩子，海报体现这个观看理由；按发布目的另写行动邀请，不直接照抄产品销售口号，也不虚构制作耗时、成本、客户反馈或流量保证。

## 真实体验与个人判断

工具分享默认加入有依据的个人视角，让读者知道“我为什么关注它、实际遇到了什么、我怎么看”。先从当前会话和本期资料提取真实经历，不只改成第一人称，也不把功能列表包装成使用感受。

| 已有依据 | 可以怎样写 |
|---|---|
| 确实使用过本期工具 | 写具体任务、实际操作和观察到的结果，再补个人感受、限制或适用条件；前后变化与数字只采用已有记录 |
| 有相关痛点，尚无本期工具的使用记录 | 写原来的工作方式、碰到的麻烦、为什么关注这个工具，以及自己会用什么标准判断它；不能写成工具已经解决问题 |
| 只有官方资料或演示 | 明确是资料梳理或演示介绍；需要补充体验时，只问一个最关键的真实场景或操作结果，不代编经历 |

可按“真实场景 → 具体卡点 → 使用过程或关注原因 → 有依据的结果与个人判断 → 相关互动”组织，按已有材料取舍。个人判断应落在具体事情上，例如哪一步省事、哪里仍需人工处理、什么条件下值得继续用；“很好用、效率翻倍、强烈推荐”不能替代体验。

经历与效果归属于实际提供者。代用户写稿时采用用户提供或其实际任务记录中的经历；Agent 为制作内容而读取文档、截图、试运行，不自动等于用户亲自用过。资料不足时如实说明本期范围，不把预期收益写成已经发生的效果。

用户只要求修改描述文案时，将这些内容补入发布正文即可，不据此改动口播、视频、配音或海报。单期经历保存在本期文案与项目资料中，本流程只维护可复用的写法和判断依据。

## Handy 示例

以下为本次修订后的写法示例，用于说明语气与结构，不是每期替换项目名即可复用的固定文本，也不代表用户已逐句认可。

```text
标题：想法太快，打字太慢？试试 Handy

话都想好了，还得一个字一个字敲出来。写邮件、记灵感、整理待办的时候，能不能直接说？

这次分享一个免费开源的桌面语音输入工具：Handy。点进输入框，按住快捷键说话，松开后就能把识别出的文字粘贴进去。

它还有一个特点：本地转写。先下载合适的模型，之后日常识别可以离线完成，录音不用为了转写上传云端。

这期视频把基本用法和第一次使用要做的设置过了一遍。中文输入记得选支持中文的模型，先录一句试试；专有名词和标点，最后再检查一下。

如果把打字换成说话，你最想用在哪个场景？欢迎留言，觉得有用记得点赞、关注。

项目：https://github.com/cjpais/Handy
官网：https://handy.computer

#Handy #开源工具 #语音输入 #效率工具
```

示例中的产品信息属于这次内容，新一期仍按当期资料核实；不要把示例当作长期不变的产品说明。

## 交付与维护

每期输出独立的 `发布文案.txt` 或 `发布文案.md`，提供可直接使用的一版标题、正文、入口与话题。用户要求多选时再提供多个方案。

生成前检查本期实际内容与资料；交付前检查个人经历是否有依据、是否混淆实际使用与关注原因、感受和判断是否具体、互动问题是否相关、链接是否正确。若文案在最终 ZIP 生成后被修改，同时更新 ZIP 并核对包内文案与外部文件一致。
