# 分镜与可见状态

各场景按需要用本页规划内容，视觉语言见 [画面与图解](visuals.md)，渲染接口见 [Remotion 接口](../tools/remotion.md)。目标是让不同主题都能得到可检查的制作过程，质量仍依赖资料、叙述判断和实际评审。

## 先确定要解释什么

从用户请求提取受众、他们已有的知识、看完应理解或能完成的事、使用场景、已确认的风格与交付要求。使用已有上下文，不重复提问。没有用户必须决定的缺失项时，记录合理假设并继续。

围绕真实问题选择叙述结构，而不固定套用“痛点 → 产品 → 功能列表 → 关注”。例如，选择题需要比较依据，原理题需要因果推导，教程需要操作与反馈，新概念需要定义与具体例子。先为主要论点找到可用证据或明确示意范围，再写完整口播；无法被素材支持的主张要调整。

分镜单位是一段有完整解释任务的内容，不是字幕行。保留同一对象的持续变化可以比频繁切页更清楚；页数和时长由信息与最终声音决定。

沿用小龙系列时，将 [固定问候](script.md#小龙系列固定开场) 与本期问题分别安排成短场景，再用可见瓶颈引出工具。角色、Bot 样式和背景分别选取，不把外观变化混同为任务进度；主对象汇总、派发或返回结果时要保留身份。详细动作见 [动画](animation.md#小龙与-bot-的动作编排)。

## 制作记录契约

在任务私有工作目录保存 `storyboard.md` 或等价结构化记录。以下是制作记录字段，**不是 `motion.json` 的渲染 schema**。选择足够明确、便于核对的表达即可，不要求机械填写冗余文案。

| 记录项 | 应能回答的问题 |
| --- | --- |
| 场景标识与口播范围 | 这段解释哪一句或哪组论点？最终时间段在哪里？ |
| 论点与观众疑问 | 看完需要理解什么？为什么此时需要解释它？ |
| 证据及边界 | 哪个文件、片段、数据或来源支持该主张？哪些只是示意？ |
| 画面主体与结构 | 观众看谁？为何用比较、流程、图表、演示或其他组织方式？ |
| 可见状态与变化 | 初始画面是什么？改变哪个对象或关系？结束时能看到什么？ |
| 声音触发点 | 哪个词或语义触发入场、强调或变化？获得最终词时间后如何对应？ |
| 素材与实现映射 | 使用哪些文件、哪些已支持字段或必要扩展？素材缺口怎样处理？ |
| 验收预期 | 在哪些时间点，应该观察到什么，才能判断本段解释成立？ |

“画面更丰富”“弹出功能卡”“高级感”不能独立充当可见状态。描述应具体到对象及其属性、位置、内容或连接的变化。静态论点可以保持稳定，但应有承担解释的图形或材料；无需为了满足格式虚构动作。

例如，一个操作论点的分镜应记录“选中原对象 → 属性改变 → 修改后的结果”，并列出素材里确实存在的状态。一个因果论点则记录“已知条件 → 关系形成 → 结果”，标清它是原理示意还是实际测量。两者不应仅替换同一卡片模板里的名词。

## 从分镜到时间轴

1. **检查语义与素材。** 先读完整分镜：每个关键主张有支持方式，主要对象可见，逻辑关系可解释。缺证据时补充授权素材、缩小主张或明确示意；空白浏览器占位不能当作已完成的产品镜头。
2. **完成口播与对齐。** 先生成连续声音，处理节奏，再取得最终时间映射；把口播范围回填为最终时间。规划时的估算时长保留为估算，不能冒充精确对齐。
3. **选择实际实现。** 根据解释任务使用当前渲染器支持的场景或基础组件。不要把本记录中的字段直接塞进 JSON；对照当前接口，执行验证，并查看实际画面。
4. **制作短样片。** 选择能暴露主要风险的代表性段落，例如复杂关系、真正的状态改变或密集界面。样片覆盖所选语义的完整变化和必要阅读时间，不固定秒数，也不只用一个简单开场证明全部可行。
5. **自行评审后扩展。** 按下表检查样片，修复会影响全片的布局或解释问题，再制作全片。只在缺少无法推断的用户选择或必要材料时提问；普通制作与检查不需要逐关批准。

## 可替换的分镜习惯

可以选择连续对象、漫画分格、全屏实录、步骤演示、比较或其他阅读结构，镜头数量与景别按解释任务决定。用本页的记录项核对含义，不要求所有场景套同一种布局。

静态、运动、声音、事实与文件检查统一见 [delivery.md](delivery.md)。本期先渲最能暴露难点的样片，修正遮挡、无证据主张、看不清或语义错位，再扩展全片；不要为评审而无故重写已认可的旁白。
